# 双机公网联调（54.65.44.140 × 52.215.36.68）

> 仅验证 **TCP 9000 镜像 BOOK + HEDGE**；公网 RTT 比 VPC 内网大，**不用于实盘延迟结论**。

## 角色约定（可互换）

| 角色 | 公网 IP | 启动参数 |
|------|---------|----------|
| **POLY** | `54.65.44.140` | `--node=POLY` |
| **PRED** | `52.215.36.68` | `--node=PRED` |

两台已探测：**TCP 9000 外网可达**。

## 1. 共享 MySQL

在**同一套库**执行：

```bash
mysql -h <DB_HOST> -u ... -p <库名> < docs/sql/node_route_install_2node_public_test.sql
```

确认：

```sql
SELECT node_code, peer_ip FROM node_config;
SELECT src_node, dst_node, route_json FROM node_route;
```

## 2. 安全组 / 防火墙

每台入站 **TCP 9000** 建议仅放行对端：

- A：`52.215.36.68/32`
- B：`54.65.44.140/32`

（测试期若已全开 0.0.0.0/0，务必尽快收窄。）

## 3. 部署二进制（v2 分支）

两台均拉 `v2`，同一 `run_conf` 指向该 MySQL。

**54.65.44.140：**

```bash
export RUN_NODE=POLY   # 或启动参数 --node=POLY
./arbopp --node=POLY --run_conf=prod ...   # 按你们现有 main 参数
```

**52.215.36.68：**

```bash
./arbopp --node=PRED --run_conf=prod ...
```

启动成功飞书：`node-relay-started`。失败：`strategy_entry 未启动(节点配置失败)`。

## 4. 快速验收

1. 两台 **在跑场次一致**（同一 `map_key` 集合），否则对端 BOOK 会被丢弃。
2. 日志无 `node-route-load-failed`；进程监听 `:9000`：`ss -lntp | grep 9000`。
3. 有官方盘口变动后，对端 `book_age_ms` 中镜像平台应变新（可查 `ext_data` 或内存心跳）。
4. **DryRun / 小仓** 下 Fire 一条：发起方 `ext_data.arb_id` 与对端 `HEDGE_RECV` 订单可关联。

## 5. 回退单机

```bash
./arbopp --node=ALL ...
```

不读 `node_route` 或 profile 为空时按旧逻辑四所 WS 直连。

## 6. 注意

- 公网链路延迟高，镜像 `book_age_ms` 常大于 VPC 方案。
- 代码 **未** 按 `accept_mirror_cidr` 过滤入站，靠防火墙。
- 双节点仍可能 **重复抢同一机会**，测试时优先 DryRun 或关实盘 Fire。
